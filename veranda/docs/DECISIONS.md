# Veranda: decisions and measurements

Numbered V1, V2, ... Measured values come from the gates (x16emu, 8 MHz cycle counter).

| # | Decision | Evidence |
|---|---|---|
| V1 | **One API table** (`api/veranda.api`) generates the jump tables, `veranda.inc`, `veranda.h`, the cc65 bindings and `docs/API.md` (`tools/apigen.py`). Classic GEOS calls keep their GEOS position: address = `$8800` + (GEOS 64 address - `$C100`); 47 GEOS positions Veranda does not implement return x = `UNSUPPORTED`; wide and new calls follow at `$8A00` in file order. Wide calls: X as in GEOS, Y in r11 (top or single y; text r12) and r12 (bottom). Table flags for word Y: menus bit 5 of the type byte (`WIDE_MENU`), icon tables bit 7 of the count (`WIDE_ICONS`), dialogs bit 5 of the first byte (`WIDE_DB`). | Gate spec: the include assembles with the promised values, both tables link with every entry at its address, a C program compiles and links against the bindings (cc65 2.19). |
| V2 | **Kernel build** (`tools/kbuild.py`): `kernel/exports.txt` says where each routine lives (R resident, G, G2, U, F, S, X). The resident core (`$8800-$9EFF`) is linked first; each bank is linked alone at `$A000` against the resident core's exports only, so code cannot reach into another bank except through its stub (`FARCALL`). `VERANDA.SYS` = 2 header bytes + six 8 KB banks (seven since V38: bank P); `VERANDA.PRG` = BASIC line + loader + resident image. | Builds; a direct `.import` of another bank's routine fails at link time. |
| V3 | **Boot:** the loader switches to ROM bank 0, turns off LOAD messages, finds the top six RAM banks with `MEMTOP`, copies the resident core, loads `VERANDA.SYS` with one `LOAD` (the ROM continues into the next bank), lowers `MEMTOP` and far-calls `Init`. Until the application loader (phase 5) `Init` starts `TEST.PRG` (a plain .PRG at `$0801`). `ToBASIC` restores palette entries 0-1, `MEMTOP`, the text screen and types a command for BASIC. | Gate boot: starts, draws, BASIC answers `PRINT 6*7` with 42. |
| V4 | **Bank gate:** a 13-byte resident stub per banked routine (`sta gA / lda #3i / sta gT / lda #bank / jmp FarGo`); `FarGo` pushes the caller's RAM bank and `FarRet`, maps the bank and jumps through `gJump` to the entry table. No `sei`: the interrupt handler must save the 7 bytes of `GATE_STATE` (phase 3). A first, generic gate (inline bank and index, globals under `sei`) cost 267 cycles. | Gate gfx1: a banked call costs 146 cycles more than a resident one, of which about 35 are `SetPattern`'s own work: the gate is about 110 cycles there and back (target 120). |
| V5 | **Span engine at 640x480** (`kernel/g/fb.s`): the old engine's model (first, middle, last byte with keep masks, port 1 reads, port 0 writes) with 17-bit VRAM addresses (the back screen at `$09600-$12BFF` crosses 64 KB), 16-bit rows, the stride 80 or 40 from the resident `kStride`, row * 80 computed (row * 64 + row * 16; a 480-row table cost 960 bytes of bank G, which the system font's rows needed, V6). Everything is clipped to the screen. Veranda has its own 34 fill patterns (0 paper, 1 ink, 2 50 % grey as in GEOS). | Gate gfx1: a shape drawn at y 20 and at y 320 is the same row for row on both screens; CopyRect, ScrollRect, RecoverRectangle, ImprintRectangle, TestPoint correct. Full-screen fill 64 ms, full-screen copy 97 ms (59 and 88 with the row table; the byte loops alone: 19 and 38 ms; the rest is per-row setup: room later, FX). |
| V6 | **Text** (`kernel/g/text.s`): GEOS fonts, y = the baseline (as GEOS: underline on the row below it), each character opaque in its box. A run of characters is rendered into a 32-byte by 32-row strip in RAM and sent to VERA one row at a time (FBOP_BUF, reverse as the XOR value): one VERA seek per row of a run instead of one per row of every glyph. Glyph rows go in chunks of up to 8 pixels (a 16-bit window shifted into place, bold as `v OR v >> 1`); italic shifts row r by `(baseline + 2 - r) / 2` (found against GEOS 64). Veranda's own system font (`tools/mkfont.py`, 9 rows, baseline 6) also exists as left-aligned rows: the plain system font takes a fast path (one unrolled shift a row). A run ends 40 pixels before the strip does (italic and the spill bytes). All GEOS string codes; outline is drawn plain for now. | Gate gfx1: 244 us a character (target 250; the first version took 577 us: a bit loop with a per-pixel `SetBit`); a system font line equals what `tools/mkfont.py` draws, pixel for pixel. |
| V7 | **Classic calls are shims in bank G2** over the wide ones in bank G (they keep r11/r12); `GraphicsString` and the bitmap decoder (GEOS's compacted format) in G2, rows through a resident row buffer and `WriteRow`. **Calls whose input is a flag** (DrawLine, DrawPoint: N recover, C ink) have a resident shim that turns the flags into a mode in a: the bank gate's `clc`/`lda` destroy them. The `i_` calls are resident (they read the caller's return address; the parameters may be in any bank); `PutString` and `GraphicsString` leave r0 past their 0 (`i_PutString`, `ESC_GRAPHICS`). Lines use GEOS's midpoint rule (error `2*minor - major`). | Gate gfx: `tests/scene.s` (rectangles, frames, lines, points, text in every style, PutDecimal both ways, PutChar, GraphicsString, bitmaps with all three count kinds, BitmapClip, recover, imprint, every inline call) assembled for GEOS 64 (`build/gen/geos64.inc`) runs on the GEOS 64 KERNAL in the old project's simulator; Veranda in 320x240 draws the same 8,000 bytes on both screens. |
| V8 | **The interrupt entry came early** (`kernel/res/irq.s`): the ROM's handler moves VERA's address registers (the screen editor's cursor; D36 of the old project). The entry saves VERA's CTRL and both ports' addresses and the bank gate's state, runs the ROM's handler through a fake interrupt frame, and restores them. | Without it the scene crashed or drew wrong at random (two runs of the same program differed). |
| V9 | **The constants are GEOS's** (string codes 8-27, style bits, GraphicsString codes, dialog positions, header and directory offsets, errors): a first table had guessed values. Veranda adds `FILE_EXISTS` 15 and `TOO_MANY_FILES` 16. | Gate spec; the scene uses them on both sides. |
| V10 | **The interrupt** (`kernel/res/irq.s`): saves `ram_bank`, r0-r15 and the kernel's zero page `$3F-$4F` (not GEOS's `$22-$3E`: the interrupt sets `pressFlag` and the mouse there, and restoring them undid every move and click), VERA's CTRL and both ports' addresses, the bank gate's state; runs the ROM's handler, then `intTopVector`, bank X's work (random, double-click count, a one-second tick for the clock, the mouse, the pointer sprite, process timers), the `Sleep` counters, `intBotVector`. | GEOS saves r0-r15 the same way. Gate `input` draws the GEOS 64 scene 20 times with a moving pointer and compares it with GEOS 64's; a control kernel built with `-D NO_VERA_RESTORE` must fail it, and does (513 and 6,340 bytes differ). Cost: text 244 to 249 µs per character. |
| V11 | **The mouse is relative** (as D34 and D68 of the old project): the pointer moves by the change of `mouse_get`'s position (range 2040x2040, centred again near an edge, but only on a frame where it moved: a device that reports a fixed position, like the headless emulator's, called `mouse_config` every frame and cost about 8,000 cycles per frame). `mouseSource` replaces the device; a new source's first position is a start, not a move. Button changes: the program's `mouseVector` if it set one, else the menus and icons (bank U), then `otherPressVec` for presses and releases (`mouseData` bit 7). | GEOS moves the pointer itself (menus, dialogs, `StartMouseMode`). GEOS's `otherPressVec` sees releases too (paint programs need them). |
| V12 | **Keys**: `GETIN` from the main loop, not the interrupt (it reads whatever channel is open), in ISO mode; a 16-key queue of GEOS codes (`GetNextChar`, `keyData`, `KEYPRESS`). The ROM's key number hook (`$032E`) turns Alt + a letter or digit into a shortcut (`SHORTCUT` OR the character) before the ISO key map makes it a Latin-9 character. `ToBASIC` puts the hook, PETSCII mode, the mouse and the sprites back. | GEOS's Commodore-key shortcuts; Alt is the X16's nearest key. |
| V13 | **Processes and Sleep** as GEOS: a table of `.word routine, timer`, all frozen after `InitProcesses`; timers count in the interrupt, the routines run from the main loop (`appBank` mapped). `Sleep` keeps the caller's return address and returns to the caller's caller; the main loop continues the caller when its count is 0 (8 at a time). | Gate `input`: a scripted session (moves, a click, two faults, three processes, two keys, a Sleep) gives the expected log, the same in two runs. |
| V14 | **Menus and icons** (`kernel/u/menu.s`) are written from a behavioural description of GEOS 64's (geometry, drawing order, the item boundaries, the flash, the fault rules), not from its code; gate `ui` compares sessions with GEOS 64 running in the simulator, on a test kernel whose system font is GEOS 64's (a fixture built at gate time). Differences, on purpose: the flashes wait on a kernel timer (`uiTimer`, `UiWake`) instead of `Sleep`, whose continuation would run with the application's bank mapped; `RecoverVector` 0 means "Veranda chooses" (the save-under stack when the application draws to the foreground only, else the back screen) instead of a white fill; the pointer is placed on a vertical menu's item without GEOS 64's lost carry; an over-long item is clipped by PutString's own rule. Kernel banks call application code through `AppJsr` (resident: maps `appBank` and back). | Applications see GEOS's behaviour; the save-under stack makes "draw to the foreground only" work with menus. |
| V15 | **Dialog boxes and GetString** (`kernel/u/dlg.s`, `getstr.s`; the prompt in `kernel/x/prompt.s`), from a behavioural description of GEOS 64's. DoDlgBox keeps the application's state (GEOS's variables, menus and icons, processes, sleeping routines, GetString's state, sprites 1-7), draws, and runs the ordinary main loop; RstrFrmDialogue restores, recovers, resets the stack to DoDlgBox's entry and returns through the bank gate's own frame. Differences: the system icon pictures are Veranda's own (`tools/mkicons.py`, resident, because bank G draws them); the default box is GEOS's in 320x240 and centred in the 640 modes; the dialog's icon table is WIDE_ICONS; WIDE_DB (bit 5) gives word top and bottom; the prompt is an 8x64 sprite (no Y expansion); DBGETFILES came in phase 7 (V22); FUTURE1-4 skip two bytes. | Gate `ui`: three dialog boxes (text, a bold line, a text input typed into with a backspace, OK, CANCEL, DBVARSTR, YES, NO, DBSYSOPV) equal GEOS 64's at four frames, the system icon areas left out; a 640x480 session over a foreground-only application gets its screen back exactly (the save-under stack); after every session the kernel banks' code is unchanged. |

| V30 | **The colour map** (`ColorRect`, bank S, `kernel/s/color.s`): a **paper colour per card** (8 x 8 pixels), from a tile layer **under** the bitmap; the ink stays one colour. What VERA allows (its reference and the emulator's renderer, `video.c`): layer 1 is drawn over layer 0; colour 0 of a layer is transparent (the screen shows palette entry 0 there); a bitmap layer's palette offset applies to all its pixels (`reg_layer[layer][4]` per layer), so its ink is one palette entry for the whole screen; a 1 bpp tile layer in 16-colour mode gives each tile a foreground (attribute bits 0-3) and a background (bits 4-7). So: with the map on, the bitmap moves to layer 1 (its paper pixels are 0: transparent) and layer 0 is a 1 bpp tile map at `$1AC00` (128 x 64 entries of 2 bytes: VERA's map widths are 32-256, 80 cards need 128; 16 KB of the 17 KB free), every entry tile 0, whose 8 bytes are 0 (at `$1E800`, map row 60: off the screen; a tile base is a multiple of 2 KB), so a card shows its background: colour 0 is transparent again and shows the normal paper. Both layers have the same scale: a card is 8 x 8 bitmap pixels in every mode. **Per-card ink is not possible** with a 1 bpp bitmap: the ink pixels are the bitmap layer's own and take its one palette offset; a tile layer over the bitmap would hide it (its pixels are opaque wherever they are not 0); the bitmap's bytes cannot be a tile layer's tiles (a tile is 8 consecutive bytes, a bitmap row 80 apart). The map is off until the first `ColorRect` (which clears it; a = $FF or `SetVideoMode` hides it; `ToBASIC` too); menus and dialog boxes do not save colours (they draw in the bitmap; the cards keep theirs). `tools/check_vera.py` accepts both displays; `tools/vram2png.py --color` composes the picture as VERA shows it. | Gate `color` (tools/gate_color.sh): eight areas (overlapping, clipped, off the screen, back to 0): the map's 4,800 cards as the areas give them, every tile 0; the composed picture has every paper pixel in its card's colour and the ink in entry 1 (pixel for pixel); after ColorRect $FF and after SetVideoMode the plain display again.
